# ClickHub audit — 2026-09-25

## Scope

Reviewed the existing seven tools, shared UI, routing, local storage, clipboard handling, source organization, dependency tree, and static build. Added ten browser-only tools and extended regression coverage to all 17. This is an engineering review with automated checks, not a formal security certification or complete WCAG conformance assessment.

## Findings fixed

| Finding | Resolution |
| --- | --- |
| Dark theme changed variables but the page still used hardcoded light background and text | Root foreground/background now use theme tokens |
| Muted text and several icon colors failed minimum contrast checks | Updated light-theme text/icon colors and dark-theme accents |
| JSON results could remain stale after editing input | Clear output and status when input changes; explain JS number/duplicate-key limits in the UI |
| Password results could remain visible after invalid lengths | Clear output on edits and on validation failure |
| Failed preference writes were silent | Show a non-blocking notice while preserving in-memory behavior |
| Re-rendered cards disrupted focus after closing a modal or favoriting a tool | Explicitly restore focus to the relevant card control, or search if it is no longer visible |
| Unknown tool hashes failed silently | Display a message and normalize the route |
| Copy handlers could target a different tool after navigation | Capture the tool's output and avoid updating detached views |
| New asynchronous operations needed stale-result protection | Shared form supports async operations, disables repeated submits, and invalidates output after edits or unmounting |
| Browser tests existed but had never run successfully | Installed an isolated Chromium package and supplied missing packaged libraries; ran tests against the production build |

## Validation results

- **21 unit tests:** pass, covering original utilities, ten new tools, empty/invalid inputs, numeric boundaries, hash vectors, malformed encodings, date ranges, duplicate URL parameters, exact large integers, and blocked/corrupt storage.
- **34 browser tests:** pass in Chromium using desktop and Pixel 7 viewport/device emulation. Covers all 17 tools, favorites/theme persistence, category filters, recent tools, reloadable hash routes, back navigation, focus restoration, blocked storage, inert user markup, stale-result handling, and local file hashing.
- **Automated accessibility:** the browser suite runs axe WCAG A/AA checks on the dashboard and a representative calculator in both themes and both viewport profiles; no violations in those scans.
- **Production build:** succeeds under `/ClickHub/`; browser tests load the production bundle and refresh deep links.
- **Dependency audit:** `npm audit` reports zero known vulnerabilities at review time. No third-party production runtime packages are bundled.
- **Privacy review:** source contains no API integration, telemetry, or file-upload path. A browser test confirms text/file hashing makes no additional network requests after loading. Tool values use text/value assignment rather than insertion into HTML.
- **Visual review:** inspected a desktop dark-theme screenshot after the theme correction; responsive overflow assertion passes in the navigation tests.
- **Repository structure:** tool logic/views remain inside category/tool folders. Build output, reports, local data, dependencies, and scratch screenshots are ignored. Root contains only the entry HTML, README, package metadata, and essential configuration.

## Reproducing browser tests

Normal setup:

```sh
npm ci
npx playwright install --with-deps chromium
npm test
npm run test:e2e
npm audit
```

The standard Chromium download failed in this sandbox with a TLS reset, and Debian dependency repositories were unreachable. An isolated `@sparticuz/chromium` package (outside this repository) supplied Chromium and its bundled NSS/NSPR libraries. Tests were run with:

```sh
LD_LIBRARY_PATH=/home/user/browser-check/libs/lib \
CHROMIUM_EXECUTABLE=/tmp/chromium npm run test:e2e
```

These machine-specific binaries are not project dependencies and are not committed. Future sessions may need to reinstall a browser. The optional executable-path setting allows a local Chromium installation instead.

## Boundaries and remaining work

- No deployment workflow is configured. GitHub Pages publishing and permissions still need setup; building locally does not publish a site.
- No service worker, offline installation, cloud sync, login, notes, task manager, or habit tracker yet.
- Browser tests use Chromium and emulated mobile settings, not Safari, Firefox, or real phones. Manual screen-reader and comprehensive keyboard testing remain outstanding.
- Automated accessibility scans sample the shared shell and a calculator; they do not certify every tool or every possible state.
- Password generation uses Web Crypto with rejection sampling; it does not guarantee each character class appears. This is not a password manager.
- JSON formatting uses JavaScript parsing, with its documented precision and duplicate-key limitations. Text character counts are UTF-16 code units.
- Hashing is memory-bound and capped at 25 MiB. SHA digests are not encryption or secure password storage. Inputs are not saved, but this does not guarantee secure erasure from browser memory.
- Financial tools assume fixed rates, no fees, and the displayed compounding/payment convention. They are estimates, not financial advice. BMI is an adult screening estimate, not diagnosis.
- URL inspection does not visit links or assess their safety; credential flags do not imply that arbitrary query parameters are free of sensitive data.
- Browser preferences can be cleared; a warning is shown if storage writes fail. No persistent personal records are stored by current tools.
